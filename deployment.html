Multi-Balance Data Acquisition — Deployment Architecture

Radwag balances → MOXA NPort 5150 → pharma LAN → central collector PC → Supabase

Complete configuration and operating procedure for connecting N Radwag balances to a central Windows 10 collector via MOXA NPort 5150 serial device servers, with onward replication to Supabase.

1. Target architecture

2. IP addressing — must be done before deployment

Every NPort ships on 192.168.127.254. Your Mac is currently on the same 192.168.127.0/24 island, which is why it works on the bench. The moment two units are plugged into the pharma LAN with factory settings you get an IP conflict, and neither will be reachable.

Fix: before each unit leaves the bench, give it a unique address on the plant subnet (Network Settings → IP address / Netmask / Gateway → Save/Restart). Ask IT for a reserved block, one per instrument:

InstrumentNPort IPPortLocation
Balance 0110.20.30.114001QC Lab A
Balance 0210.20.30.124001QC Lab A
Balance N10.20.30.1N4001…
Collector PC10.20.30.10—Server room

Use static IPs, or DHCP reservations by MAC. Never plain DHCP — the collector addresses NPorts by IP and a lease change silently breaks acquisition.

3. Bench provisioning procedure (per unit)

  1. Connect the new NPort directly to the Mac; set the Mac to 192.168.127.10/24.
  2. Browse to http://192.168.127.254, password moxa.
  3. Change the admin password. Factory default must not reach the plant LAN.
  4. Network Settings → set the assigned static IP, netmask, gateway.
  5. Serial Settings → 4800, 8, None, 1, flow control None, RS-232 (match the balance).
  6. Operating Settings → TCP Server Mode, Local TCP port 4001, Max connection 1.
  7. Accessible IP Settings → allow only the collector PC's IP.
  8. SNMP → set a non-default community string, or disable SNMP.
  9. Save/Restart, then re-verify the live baud over SNMP or the console.
  10. Label the unit with its IP and the instrument it serves.
Verify before shipping to the floor: loopback pins 2–3 on the NPort's DB9 and confirm an exact echo. That proves the unit before it is ever blamed for a cabling fault in the field.

3b. Windows 10 — network configuration

Set the static IP on the collector PC

  1. Settings → Network & Internet → Ethernet → click the adapter name.
  2. Under IP settings click Edit.
  3. Change Automatic (DHCP) to Manual, switch IPv4 to On.
  4. Enter: IP 10.20.30.10 · Subnet prefix length 24 · Gateway 10.20.30.1 · DNS as supplied by IT.
  5. Save.

Command-line equivalent (run PowerShell or CMD as Administrator):

netsh interface ipv4 show interfaces
netsh interface ipv4 set address name="Ethernet" static 10.20.30.10 255.255.255.0 10.20.30.1
netsh interface ipv4 set dns    name="Ethernet" static 10.20.30.5
ipconfig /all

Bench-provisioning a new NPort from Windows

A factory NPort answers on 192.168.127.254, so the PC needs a temporary address on that subnet. Add a second IP rather than disturbing the plant address:

netsh interface ipv4 add address name="Ethernet" 192.168.127.10 255.255.255.0

Configure the unit, then remove the temporary address:

netsh interface ipv4 delete address name="Ethernet" 192.168.127.10

Verify connectivity to each NPort

ping 10.20.30.11
Test-NetConnection 10.20.30.11 -Port 4001        # PowerShell

TcpTestSucceeded : True confirms the serial port is reachable.

Windows Firewall

Outbound rules only — the collector initiates every connection, so no inbound ports need opening for acquisition.

New-NetFirewallRule -DisplayName "Balance NPort out" -Direction Outbound `
  -Protocol TCP -RemotePort 4001 -RemoteAddress 10.20.30.0/24 -Action Allow
New-NetFirewallRule -DisplayName "Supabase HTTPS out" -Direction Outbound `
  -Protocol TCP -RemotePort 443 -Action Allow

If the web UI is bound to 127.0.0.1 it needs no firewall rule at all. Only open inbound TCP 8000 if other machines must reach the dashboard, and restrict it by source address.

Run the collector as a Windows service

It must survive reboot and logoff. Using NSSM (nssm.cc):

nssm install BalanceCollector "C:\Python312\python.exe" "C:\balance\balance_server.py"
nssm set BalanceCollector AppDirectory C:\balance
nssm set BalanceCollector Start SERVICE_AUTO_START
nssm set BalanceCollector AppStdout C:\balance\logs\out.log
nssm set BalanceCollector AppStderr C:\balance\logs\err.log
nssm start BalanceCollector

Alternative without extra tools — Task Scheduler: trigger At startup, Run whether user is logged on or not, Run with highest privileges.

Time synchronisation

w32tm /config /manualpeerlist:"ntp.corp.local" /syncfromflags:manual /update
w32tm /resync
w32tm /query /status

The collector clock is the reference timestamp for every record, so it must be disciplined to the plant NTP source.

Protect the secrets file

icacls C:\balance\.env /inheritance:r
icacls C:\balance\.env /grant:r "NT SERVICE\BalanceCollector:(R)"
icacls C:\balance\.env /grant:r "Administrators:(F)"

Consider enabling BitLocker on the collector's drive; the .cred file holds the collector's encrypted Supabase credentials.

4. Collector PC

One process, one thread per NPort, one TCP connection each. NPort Max connection = 1, so only the collector may connect — no second tool, no engineer's laptop, while it runs.

5. Supabase

Supabase configuration is mandatory. The collector keeps no local database; until Supabase is configured it captures nothing. In self-hosted mode it creates the two tables automatically on first connect; in cloud mode (*.supabase.co) it reaches Supabase over REST, which cannot issue DDL, so apply the migration (*_moxa_and_balance_integration.sql) to the project first.
-- "moxaServers": one row per MOXA NPort gateway
create table if not exists public."moxaServers" (
  id                uuid primary key default gen_random_uuid(),
  host              text not null unique,
  port              integer not null default 4001,
  name              text,
  enabled           boolean not null default true,
  status            text default 'idle',
  last_seen         timestamptz,
  moxa_password_enc text,            -- device password, ENCRYPTED (never plaintext)
  collector_id      text,
  created_at        timestamptz default now(),
  updated_at        timestamptz default now()
);

-- balance_integration_data: one row per completed session, FK -> "moxaServers"
create table if not exists public.balance_integration_data (
  id           uuid primary key default gen_random_uuid(),
  moxa_id      uuid not null references public."moxaServers"(id),
  moxa_name    text not null, moxa_host text not null,
  kind         text not null check (kind in ('weighing','adjustment')),
  label        text not null,
  inst_id text, reg_no text, balance_sn text, operator text,
  started_at   timestamptz, finished_at timestamptz,
  raw_text     text not null,         -- verbatim transcript, the legal record
  blocks       jsonb not null default '[]'::jsonb,  -- [{seq,kind,received,body}]
  bytes        integer not null default 0,
  collector_id text, created_at timestamptz default now(),
  unique (moxa_id, started_at, label)  -- idempotent re-sync
);
alter table public."moxaServers" enable row level security;
alter table public.balance_integration_data enable row level security;
  • The collector writes with the service role key (cloud) or the admin Postgres role (self-hosted) only. It must never reach a browser or operator workstation.
  • The LIMS reads these tables read-only and column-scoped, so MOXA device passwords never leave the database.
  • The unique constraint makes retries idempotent — a failed write can be replayed without creating duplicates.
  • Keep raw_text verbatim. Parsed fields are a convenience; the transcript is the record that stands up to audit.
  • Records are insert-only. No updates, no deletes — revoke those in RLS.

7. Regulated-environment notes (GxP)

  • Clock discipline. Balance RTC drift was measured on the bench. Record both the instrument's printed timestamp and the collector's NTP-synced receipt time.
  • Nothing invented. The collector stores what the balance transmitted, verbatim. It never fabricates or back-fills metadata.
  • Qualification. Expect IQ/OQ/PQ. The bench loopback test and a documented end-to-end sample per instrument form the evidence base.
  • Change control. NPort serial settings and balance printout templates are configuration items — record them per instrument and re-verify after any change.
